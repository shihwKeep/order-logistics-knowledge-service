# PDF 版面感知解析设计

## 1. 背景与问题

当前 `PdfDocumentParser` 使用 PDFBox 按页提取纯文本，每页固定生成一个 `ParsedUnit`，并把 `titlePath` 写为空字符串。这种实现能够完成文本抽取、Token 切分和索引，但存在两个明确缺口：

1. 页眉、页脚和页码会进入正文，造成无效关键词和向量噪声。
2. PDF 中的章节层级没有进入 `titlePath`，无法进行标题字段加权、章节级引用和准确的证据展示。

本次改造面向通用生产级 PDF，不为现有四份测试文档编写专用固定词组规则。章节编号正则只作为标题判断的辅助证据，不能单独决定标题类型。

## 2. 目标

- 保留 PDF 页内文本的字体、坐标、页码和视觉行信息。
- 自动识别并删除跨页重复的页眉、页脚及纯页码。
- 综合版面与文本特征识别多级标题。
- 支持一页包含多个章节，并为每个正文单元生成稳定的 `titlePath`。
- 保持文本型 PDF 与扫描型 PDF 的 OCR 回退能力。
- 保留原始抽取文本用于审计，只清洗用于检索的有效文本。
- 重新处理现有四份 PDF 后，使 MySQL、Elasticsearch、Milvus 三处数据一致。

## 3. 非目标

- 不实现完整的 PDF 视觉理解模型或商业 Document AI 服务。
- 不保证恢复任意复杂 PDF 的原始排版。
- 不根据某个业务文档标题列表建立白名单。
- 不在本次改造中调整混合检索、RRF 或重排策略。

## 4. 方案比较

### 方案 A：仅使用纯文本和标题正则

实现简单、成本低，但容易把编号列表识别成标题，也无法可靠区分页眉、正文和视觉标题，泛化能力不足。

### 方案 B：PDFBox 版面特征与文本证据融合（采用）

通过 PDFBox 的 `TextPosition` 收集字体大小、字体名称、粗细线索和坐标，将字符聚合为视觉行；再结合跨页重复区域、上下留白、行长、编号结构和字体层级识别页眉页脚与标题。该方案不引入外部服务，能覆盖文本型 PDF，并可与现有 OCR 坐标结果共享后处理逻辑。

### 方案 C：外部版面模型或 Document AI

对复杂表格和多栏布局的准确率可能更高，但增加外部依赖、费用、数据合规和可用性风险，超出当前阶段需求。

## 5. 架构与职责

### 5.1 版面抽取层

新增独立的 PDF 版面抽取组件，负责把每页字符聚合为有序视觉行。每个视觉行至少包含：

- 文本内容；
- 页码；
- 起止坐标；
- 平均及最大字体大小；
- 字体名称和粗体线索；
- 与上一行、下一行的垂直间距。

该组件只描述版面事实，不负责业务标题判断。

### 5.2 页眉页脚清洗层

对全部页面的顶部和底部区域进行归一化统计。归一化时移除页码差异、合并多余空白，并保留原始文本映射。

满足以下条件时才把某行视为重复页眉或页脚：

- 位于页面顶部或底部的限制区域；
- 归一化文本在足够比例的页面重复出现；
- 不是仅在封面或单一章节出现的唯一标题。

纯页码可以单独识别。封面标题、章节首页标题和少数页面的特殊提示必须保留。

### 5.3 标题识别层

标题判断使用多证据评分，证据包括：

- 字体大小相对正文基线明显增大；
- 字体具有粗体或标题字体特征；
- 行前后留白较大；
- 文本较短且单独成行；
- 位于页面或内容区的显著位置；
- 具有章节编号结构；
- 与邻近正文在版面上形成明确边界。

编号列表、表格序号和普通句子不能仅凭正则被判定为标题。标题级别优先由字体层级确定，编号深度作为辅助；无法可靠判断时按正文处理。

### 5.4 结构化单元构建层

解析器维护跨页标题栈。遇到标题时更新对应层级，并将后续正文归入当前标题路径。一页存在多个标题时生成多个结构化单元，而不是继续强制“一页一个单元”。

`titlePath` 使用稳定、可读的路径格式，例如：

```text
退款审核与资金风险控制规范 > 5 优惠、积分与赠品处理
```

正文跨页但没有新标题时继承上一页的标题路径。目录页可以保留为独立单元，但不能让目录条目污染后续标题栈。

### 5.5 OCR 降级路径

扫描页继续使用现有 OCR 服务。OCR 结果如果包含文字块坐标，则复用区域清洗、行聚合和编号结构；由于缺少可靠字体信息，标题判断阈值应更保守。

当 OCR 无法可靠恢复标题层级时：

- 保留正文和页码定位；
- 继承已知的上一层标题路径；
- 不凭空生成标题；
- 继续保留低置信度标记供人工校正。

## 6. 数据与版本策略

- `raw_text` 保存页面原始抽取结果，不删除页眉页脚。
- `effective_text` 保存清洗和结构化后的检索正文。
- `title_path` 保存识别后的章节路径。
- `location_label` 继续保存页码；需要时可附加页内章节说明，但页码必须可稳定解析。
- 解析器版本从 `pdfbox-3-ocr-v1` 升级为 `pdfbox-3-ocr-v2`。
- 新版本解析结果通过现有摄取事务和索引 Outbox 流程进入 MySQL、Elasticsearch 和 Milvus，不新增旁路双写。

已有文档不会静默修改。实现完成后对四份测试 PDF 执行受控重建，确认新解析版本、切片数和索引清单后再替换发布层结果。

## 7. 错误处理与安全边界

- 版面分析失败时，本轮文档进入现有解析失败流程，不生成半完整索引。
- 单页无法识别标题不应导致整份文档失败，应回退为正文单元。
- 清洗后的页面为空但原文有内容时，回退到原始正文，防止误删整页。
- 标题路径长度受数据库字段长度限制，超长路径按层级从外向内做确定性裁剪，并保留当前最近标题。
- PDF 页数、文件大小、OCR 置信度和现有资源限制保持不变。

## 8. 测试设计

### 8.1 单元测试

- 多页重复页眉、页脚和变化页码被移除。
- 仅封面出现的标题不会被当作重复页眉删除。
- 字体层级和编号结构共同识别一级、二级标题。
- 普通编号列表不会误判为章节标题。
- 单页多个章节会生成多个结构化单元。
- 跨页正文继承上一页标题路径。
- 清洗结果为空时回退原文。
- OCR 坐标缺失时执行保守降级。

### 8.2 集成测试

生成至少三页的测试 PDF，包含封面、重复页眉页脚、多级标题、正文和编号列表，验证：

- `raw_text` 保留原始内容；
- `effective_text` 不含重复页眉页脚；
- `title_path` 层级正确；
- 切片继承正确标题路径；
- 解析器版本为 `pdfbox-3-ocr-v2`。

### 8.3 回归验证

- 现有 PDF 与图片 OCR 测试继续通过。
- Markdown、HTML、DOCX、XLSX 和 PPTX 解析行为不变。
- 四份业务 PDF 重建后，MySQL、Elasticsearch、Milvus 数量一致。
- 每个知识库至少执行一个正向召回、一个跨章节问题和一个无依据拒答问题。

## 9. 验收标准

- 四份测试 PDF 的业务章节切片均具有非空 `titlePath`，封面或目录等无自然章节的单元允许为空。
- 重复页眉、页脚和纯页码不再进入 `effective_text` 与最终切片正文。
- 原始文本仍可通过 `raw_text` 审计。
- 已有四个正向检索问题继续返回正确文档和页码，且标题路径可用于引用展示。
- 全量自动化测试通过，其他格式解析器无回归。
- 重建后 MySQL、Elasticsearch 与 Milvus 的已发布切片数量一致。
